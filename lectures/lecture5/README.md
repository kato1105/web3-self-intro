## ⚙️ 実装された機能（v2 最小スコープ完成版）

「どこまで動けばバグの解決方法とプロダクトの価値が伝わるか」を突き詰め、以下の機能を完全に実装しました。

1. **地名・駅名の手動位置検索**
   - 無料の住所検索API（OpenStreetMap Nominatim）をバックエンド不要で直接連携。地名や駅名を入力するだけで、地図が瞬時にその場所へ移動し、指定された現在地ピンが立ちます。GPSが使えないPC環境や、未来に行く予定の場所を調べる際に非常に便利です。
2. **位置連動型 3km自動絞り込み＆リアルタイム距離ソート**
   - GPS現在地、または手動検索した地点から「**半径3km以内**」にあるスポットのみを自動的に抽出して表示します。
   - スポットリストは、現在地から**最も近い順にリアルタイムに自動ソート**され、各カード内に現在地からの移動距離（例: `🚗 180m`、`🚗 1.5km`）が自動計算されて表示されます。
   - 周辺3km以内にスポットが無い場合は、渋谷・新宿・東京などの主要駅を検索するように案内する親切なUXメッセージが表示されます。
3. **「店舗詳細（Google Map）リンク」の追加**
   - スポットカードおよび地図上のピンの吹き出し内に、「**🌐 詳細 / 🌐 地図・詳細**」リンクを設置しました。ワンタップで店舗のGoogle Mapsページへ直接飛び、詳細なレビューやルート案内を確認できます。
4. **混雑状況のワンタップ投稿と自動リセット**
   - ユーザーが「空きあり（🟢）」「普通（🟡）」「混雑（🔴）」の3段階をコメント付きで簡単に投稿できます。
   - 投稿データは `localStorage` に保存され、**30分以内のアクティブな投稿のみ**を表示に反映する自動期限切れ仕様となっており、常に「新鮮なリアルタイム情報」だけがマップ上に残るようになっています。
5. **アプリ風SPA（シングルページアプリケーション）デザイン**
   - PCでは左右分割、スマホや拡大表示時は上下分割に自動でフレキシブルに切り替わります。
   - ブラウザ全体のスクロールバーを排除し、地図とリストがそれぞれ別々に独立してスクロールする設計となっており、ネイティブアプリさながらの高級感のある操作感を実現しました。

## 💡 直面した技術的課題と、Web3・トークンエコノミーによる解決ビジョン

- **直面した最大の課題（情報のリアルタイム性）**:
  - カフェや自習室の「リアルタイムの混雑情報」は、Google Mapsの公式APIでも公開されていません。API経由でリアルタイムな満席情報を自動で取得することは、実質的に不可能です。
- **Web3を融合した解決のストーリー**:
  - 本プロダクトはこの課題に対し、**「混雑状況を報告したユーザーに、インセンティブとしてトークン（JOINやICHIGO）を付与する」** というトークンエコノミー設計を提案します。
  - 中央集権的なAPIから情報を引っ張ってくるのではなく、Web3ならではのインセンティブでユーザーの自発的な「データ提供行動」を促します。
  - これにより、「誰もクチコミを投稿しない」という問題を乗り越え、ユーザー同士が協力して正確なリアルタイム混雑情報を集め合う**「分散型データインフラ（DePIN / Decentralized Physical Infrastructure Networks）」**を構築するビジョンを描いています。
